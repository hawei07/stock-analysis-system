# AI 分析数据输入深度模式

> 从芒格分析迭代中提炼：分析质量不取决于 Prompt 或模型，取决于**喂给 AI 的数据深度**。

## 三阶段演进

### 阶段 1：纯 DB 数据 + AI 训练知识
- **输入**: 只有 custom_financials 的表格数据
- **输出**: ~800 字，泛泛而谈，无具体数字
- **问题**: DeepSeek 凭训练数据编造数据（茅台的 PE 从 18 变成 30）
- **教训**: **绝不相信 AI 自己能算/记得任何财务数字**。所有数据必须显式传入。

### 阶段 2：+ 搜索标题（本阶段最关键的修复）
- **输入**: 6 维度 DuckDuckGo 搜索，每条只返回链接标题（30-50字）
- **输出**: ~2391 字，有一定深度但仍基于概括
- **问题**: DuckDuckGo Lite 改版（`class="result-link"` 消失）导致搜索全空
- **修复**: 重写 HTML 解析器，匹配所有 `<a href>` 外链

### 阶段 3：+ 页面全文抓取（当前最优）
- **输入**: 搜索到结果后，抓取前 2 条链接的**页面全文**（各 1500 字，6维度×2篇=12篇）
- **输出**: ~2630 字，含具体数据点（"12.54亿减值""和成煤矿停产""毛利率30.06%"）
- **代价**: 耗时从 20s 升到 66s（12 次 HTTP 请求）
- **结论**: 多出来的 46s 完全值得——分析从"泛泛而谈"变成"有据可查"

## 通用模式

```
分析质量 ≈ f(输入数据深度)

搜索标题（30字/条）→ 表面分析
页面全文（1500字/篇）→ 有数据支撑的深度分析
```

适用于任何"搜资料 → AI 分析"的场景：股票研究、行业报告、竞品分析、论文评审等。

## DuckDuckGo HTML 脆弱性

DuckDuckGo Lite 页面结构不保证稳定。检测搜索失效的方法：
```python
_web_search('任何关键词')  # 返回 "(无搜索结果)" 或 "(搜索失败)"
```

修复步骤：
1. `curl -s https://lite.duckduckgo.com/lite/ -d 'q=test'` 查看实际 HTML
2. 找到搜索结果所在的标签结构
3. 更新正则匹配模式
4. 验证返回值非空
